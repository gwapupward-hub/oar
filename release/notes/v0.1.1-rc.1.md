# OAR v0.1.1-rc.1 (pre-release)

This is the release candidate that clients build against: the first OAR web explorer, wallets and other integrators. It freezes the protocol surface at:

- manifest format `0.1`;
- AppRecord layout `1`;
- SAS link schemas version `2`;
- `@open-app-registry/sdk` and `@open-app-registry/cli` `0.1.1-rc.1`.

**Status: devnet deployed and verified. Mainnet: NO-GO.**

## What is in this candidate

- **Program `oar-registry`:** five instructions, deployed on devnet as `oariw8YXcYJh9sa9VcmBU3ZCdo2WVGMYPsLjEuUxfrC`. The table below states whether this binary is byte-for-byte the deployed one.
- **Devnet evidence:**
  - hash-verified deployment;
  - IDL published through Program Metadata;
  - 13-case smoke suite;
  - OAR registered as its own app, with every link verified;
  - 21-case SAS attestation rehearsal.

  See `devnet.json` and the repository's `release/evidence/`.
- **SDK hardening since the internal pre-review:**
  - Attestations from a signer the credential no longer authorizes fail closed (OAR-IR-01).
  - Manifests, proof files and backlinks that repeat a JSON key are rejected (OAR-IR-02).
  - The CLI reads manifests strictly. A confirmation timeout says to check the signature before retrying (OAR-IR-06).
- **Supply chain:**
  - GitHub Actions are pinned to commit SHAs.
  - The program is built in a digest-pinned builder, and a second clean build must be byte-identical.
  - `cargo-deny` checks advisories, licenses, bans and sources on both Rust lockfiles. `npm audit` and npm registry signature checks run on every change.

## Not in this candidate (mainnet gates)

- An independent security review. The scope is in `docs/SECURITY-REVIEW-SCOPE.md`.
- Squads multisig upgrade governance, rehearsed on devnet. Devnet upgrades are held by a single key (OAR-IR-05).
- Operations: a dedicated RPC, monitoring and a rollback rehearsal.
- A production SAS issuer. The devnet rehearsal used a TEST credential, and the default trust list is empty.
