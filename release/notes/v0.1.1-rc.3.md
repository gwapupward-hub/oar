# OAR v0.1.1-rc.3 (pre-release)

This candidate makes verification honest about outages and closes two manifest-hosting mistakes before the
developer starter is distributed more widely. The protocol surface is unchanged from `v0.1.1-rc.2`:

- manifest format `0.1`;
- AppRecord layout `1`;
- SAS link schemas version `2`.

The program binary is the one deployed on devnet; the table below confirms it byte for byte.

**Status: devnet deployed and verified. Mainnet: NO-GO.**

## Fixed

- **An RPC outage is never a failed ownership proof** (#20). In rc.2 a failed read of a program's `oar`
  metadata account became `failed` ("Disputed / invalid"), and `resolveProgram` returned `null` as if no backlink
  existed. Now:
  - `fetchProgramBacklink` returns `status: 'unavailable'`; the claim is `unverified` with a retry hint;
  - `fetchClaimAttestation` returns `status: 'unavailable'` instead of `invalid` when its reads fail;
  - `resolveApp` throws `OarRpcUnavailableError` when the AppRecord cannot be read, instead of returning `null`;
  - `resolveProgram` returns `{ status: 'unavailable', program, detail }` for outages and for a missing
    cross-cluster RPC;
  - CLI `inspect` and `resolve-program` exit `2` on an outage (exit `1` remains "absent").
  Successfully read but malformed or mismatched evidence still fails, and a missing backlink is still unverified.
- **Manifest URI policy** (#21). `checkManifestUri` refuses source-forge URLs that follow a branch, tag or `HEAD`
  (they break the record when the ref moves) and any manifest named `oar.json` (reserved for proofs). `ar://`,
  `ipfs://`, commit-pinned forge URLs and other HTTPS locations are accepted. It runs in `checkManifestHosting`,
  `buildClaimFiles`, and CLI `register`, `update` (both now confirm hosting before signing) and `claim`.

## Added

- `retryable?: true` on `LinkCheck` and `ClaimResult` for `unverified` claims whose RPC, HTTP (timeout, network,
  429, 5xx) or DNS read did not complete. Display rules: `docs/VERIFICATION-STATES.md`.
- `checkManifestUri` on the root entry point and on `@open-app-registry/sdk/register`.
- `HttpCheckError.httpStatus` and `HttpCheckError.transient`.

## Breaking changes for SDK consumers

- `resolveProgram` returns `ResolvedProgram | UnavailableProgramResolution | null`. Narrow with
  `'status' in result` before reading `result.app`.
- `resolveApp` can reject with `OarRpcUnavailableError`. Do not treat that as "no AppRecord".
- `BacklinkResult` and `ClaimAttestation` gain an `unavailable` status; `HostingCheck` gains reason `unsafe-uri`.
  Exhaustive `switch` statements need a branch for them.

Migration notes: `docs/RPC-UNAVAILABILITY.md`. The explorer's compatible change is gwapupward-hub/oar-web#13.

## Not in this candidate (mainnet gates)

Unchanged from rc.2: independent security review, Squads upgrade governance rehearsed on devnet (OAR-IR-05),
operations (dedicated RPC, monitoring, rollback rehearsal), and a production SAS issuer (the default trust list
is empty).
